# Apply blue-green to physical store generations

A database, cache, or object store remains one logical component while blue-green work temporarily maintains active and candidate physical generations. Required mode prepares a separately addressable candidate, synchronizes authoritative data or rebuilds derived data, verifies it, switches authority without losing acknowledged writes, and retains the previous generation for a declared rollback window. Store transitions are driven by environment configuration revisions and cover upgrades, upsizing, storage changes, and implementation migrations; application-defined schema migrations remain a separate concern and default to expand-and-contract compatibility. External stores qualify only when their owners expose equivalent verifiable transition capabilities. This avoids forcing availability-sensitive store changes into in-place mutation while preserving one authoritative store after handoff.
