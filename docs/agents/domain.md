# Domain docs

This is a single-context repo. Before working in an area, read the root `CONTEXT.md` and the relevant decisions in `docs/adr/`.

Use the glossary’s terms in issues, plans, code, and tests. If a proposed change conflicts with an ADR, call out the conflict rather than silently overriding it. If a domain term is unresolved, use domain modeling to settle it before adding it to the glossary.
