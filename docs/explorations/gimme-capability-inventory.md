## Evidence maturity and documentation caveats

- The committed verification gate runs Python tests, Ruff, Bandit, dependency audit, PHPStan, PHP syntax checks, Composer audit, and whitespace checks. A disposable-host integration scenario has explicit safety guards; the local rollout scenario needs no cloud/network. This inventory did **not** run the suite or contact a host/AWS. `gimme@f3b98f9:scripts/gimme-verify:13-49`; `gimme@f3b98f9:tests/integration/disposable_vm_smoke.py:18-35`; `gimme@f3b98f9:docs/reference/rollout-acceptance-evidence.md:75-84`.
- Some committed prose is out of sync: `README.md` calls ElastiCache live validation pending and says traffic splitting remains future work, while the ElastiCache live runbook records a bounded live run and the rollout acceptance matrix records implemented weighted routing. Prefer the feature-specific implementation/tests and the runbook's explicit verification limits over the stale summary. `gimme@f3b98f9:README.md:315-345`; `gimme@f3b98f9:docs/how-to/validate-aws-elasticache-live.md:53-111`; `gimme@f3b98f9:docs/reference/rollout-acceptance-evidence.md:7-59`.
- Gimme's `AGENTS.md` describes desired state as schema v3, whereas the committed README describes schema v8. This inventory avoids treating either as a migration promise. `gimme@f3b98f9:AGENTS.md:4-20`; `gimme@f3b98f9:README.md:109-119`.
